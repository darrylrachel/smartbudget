# ADR: Phase 2 backend foundation

Status: adopted, 2026-10-29. Scope: process health and reliability only.

## Context and inspection

The supplied directory is a specification folder, not a Git repository. The existing worktree at `repository-alignment/` started on `feat/phase-1-financial-engine`, commit `dd2da95`, with modified README, .gitignore and PROJECT_STATUS plus untracked server/, supabase/, Vite proxy and Phase 2 documents. Those files were copied to `../phase2-preexisting-backup` before revision. Other checkouts were untouched. The dedicated branch fast-forwards to main `885e6ea` (Phase 1 merge plus existing Pages workflow).

The application is React/TypeScript/Vite in web/, npm with a separate lockfile, strict Bundler-mode TypeScript, ESLint, node:test through tsx and Playwright Chromium. Domain modules are pure apart from standard Web Crypto hashing. Root Expo history is preserved. Existing web CI runs typecheck, lint, unit tests, build and Chromium; an existing Pages deployment workflow is outside this change. No committed backend or Supabase integration existed. The local uncommitted scaffold provided useful starting files, but lacked /health, development/typecheck scripts, shutdown handling and independent backend fixtures. Its tests depended on stale generated artifacts.

## Decisions

- **Runtime and framework:** Node >=22.12 <23 matches the repository. Fastify 5 is pinned with npm lockfile. It supplies routing, JSON Schema validation, lifecycle and test injection without a heavyweight framework. Separate server/ package avoids destabilizing web installs and keeps operating cost near zero for local work.
- **Organization:** server/src/app.ts owns HTTP setup and process-independent app construction; config.ts validates environment; local.ts owns listener and signals; tests/ owns synthetic fixtures. Add application services only with actual use cases; future persistence adapters stay outside the financial domain. No empty service/repository abstractions are introduced.
- **Shared domain:** keep the authoritative sources at web/src/domain for this increment. Backend tests import those exact TypeScript files. No modules move, no copies and no financial endpoint. tsx resolves source imports during tests; esbuild resolves extensionless imports into Node ESM for the production entry point. Before financial services ship, either bundle their direct imports the same way or extract a shared package in a separately reviewed change. Node 22 provides crypto.subtle, TextEncoder and structuredClone. Server type checking excludes DOM libraries to catch browser-only references.
- **Configuration:** PORT is optional, defaults to 3001, and rejects invalid values before listening. Loopback host is fixed for local development. No provider secrets are read, no dotenv dependency, and Supabase availability never affects startup or health. PowerShell environment variables are explicit; example files do not load automatically.
- **Supabase boundary:** retained local config, no migrations or SDK. Database/Auth will be introduced later behind authorized application services. Client input never establishes identity or household access. Exposed tables will require RLS and authorization tests; routine privileged service keys must not enter browser code. No hosted resources were accessed.
- **HTTP contract:** GET /health is unversioned process liveness and returns only {"status":"ok"}. Future business routes use /api/v1. No legacy /api/health alias is introduced. The pre-existing Vite /api proxy can support later versioned routes but health is tested directly on port 3001.
- **Validation and errors:** future routes declare JSON Schemas. Coercion, unknown-field removal and defaults are disabled. Client errors use {"error":"Invalid request"}; unknown paths use 404 {"error":"Not found"}; unexpected errors use 500 {"error":"Internal server error"}. No raw exception messages or stacks enter responses. Test-only routes exercise these conventions without adding product endpoints.
- **Logging:** Fastify structured logging is enabled by the process launcher. Automatic request logging is disabled. Request failures record generated request ID and status only, never raw exceptions, financial inputs, URLs, query strings, headers, bodies or environment values. Startup failures use fixed clear diagnostics. Future observability must preserve these limits.
- **Lifecycle:** SIGINT/SIGTERM close Fastify and drain connections, with a ten-second exit deadline. Windows process termination used by child.kill is not equivalent to POSIX signal delivery; automated Windows smoke proves process cleanup, not POSIX signal semantics.
- **Testing:** strict backend checks, real-socket health, safe errors and validation, independent allocation fixture, production startup/config failure smoke. Existing domain tests remain authoritative for cents, overflow, ordering and snapshot identity. Web typecheck/lint/build and browser suite remain required. Backend CI is added as a non-deploying job; existing deployment configuration is untouched.
- **Deployment:** no provider chosen or deployed. Production will need a patched supported runtime, explicit network binding, TLS, environment isolation, process lifecycle or serverless adapter, connection limits and secret management. Vercel remains proposed. This local listener is not a production security assertion.

## Recurrence correction

The tuple type did not guarantee runtime shape. Array.forEach skips sparse slots and comparisons involving undefined are false; Array(2), [15, <hole>] and [<hole>, 31] could return empty or incomplete forecasts instead of rejecting. Validate Array.isArray, length and both own indexes, then validate each numeric value before ordering. Missing/non-array fields now receive a domain error. Invalid values, fractions, duplicate/reversed days remain rejected. Unknown top-level adapter metadata (including an irrelevant monthly day) remains ignored because existing contracts select fields by cadence; rejecting it would be an unrelated compatibility change. Month-end collisions remain one payday, and nonleap/leap February preserve clamping. Tests demonstrated the sparse-input failure before the fix.
